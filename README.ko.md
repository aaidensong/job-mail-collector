# Job Mail Collector

Job Mail Collector는 Gmail로 받은 채용 알림 메일을 읽고, 개인 커리어 프로필과 비교해 적합한 공고를 선별하고, 허용된 경우 Google Sheets 트래커에 기록하며, 지원 링크를 ChatGPT 안에서 반환하는 재사용 가능한 ChatGPT 예약 작업 워크플로입니다.

공개 저장소에는 워크플로 로직과 템플릿만 포함됩니다. 각 사용자의 커리어 프로필, 이메일 데이터, 지원 이력은 해당 사용자의 연결된 Google 계정 안에 남습니다.

![Job Mail Collector 작업 흐름](job-mail-collector-flow-ko.png)

> 제품 동작, 연결 가능한 앱, 예약 작업 기능은 변경될 수 있습니다. OpenAI 문서 기준 마지막 확인일: 2026-09-08.

## 사용자가 실제로 하는 일

처음 사용하는 사람은 아래 정도만 하면 됩니다.

1. ChatGPT에 Gmail과 Google Drive를 연결합니다.
2. `prompts/01-bootstrap.md`를 새 ChatGPT 대화에 붙여넣습니다.
3. 온보딩 질문에 편하게 답합니다.
4. 추천된 공고 링크를 열어 실제 지원서를 제출합니다.

필요한 권한이 있으면 나머지는 ChatGPT가 처리합니다.

## 온보딩은 설문 입력이 아니라 대화입니다

사용자가 내부 구조를 이해하거나 질문마다 정확한 값 하나만 입력할 필요는 없습니다.

예를 들어 아래처럼 답할 수 있습니다.

> Senior Product Designer를 주로 찾고 있는데, 실제 업무가 제 경험과 맞으면 UX/UI, Growth, Lead 역할도 같이 보고 싶어요. B2C 제품 디자인 경력은 약 9년이고 디자인 시스템과 funnel 쪽 경험도 많습니다.

ChatGPT는 이 답변에서 필요한 정보를 모두 추출하고, 이미 확인된 내용은 이후에 다시 묻지 않습니다.

온보딩 원칙:

- 한 턴에 질문 하나
- 자유로운 자연어 답변 허용
- 어려울 수 있는 질문에는 답변 예시 제공
- 예시는 참고용이며 같은 형식으로 답할 필요 없음
- 일반 질문에는 `필수` 표시를 하지 않음
- 선택 질문에만 선택 표시
- 선택 질문에는 답변하지 않아도 된다는 안내 포함
- 좁은 필터보다 실제 경력과 강점을 먼저 수집
- 기술 설정은 가능한 한 추천 기본값 사용

경력이 많은 사용자에게는 `Senior Product Designer` 같은 직함 하나만 받고 넘어가지 않습니다. 실제 업무 범위, 문제 해결 강점, 성과, 모호한 문제에서의 판단, 협업 영향력, 리더십, 프로세스 개선, 차별화된 전문성을 파악할 수 있도록 역할에 맞는 심화 질문을 합니다.

## 직무명보다 실제 업무 적합도를 우선합니다

사용자가 말한 희망 직무명이나 직급은 기준점이지, 자동 허용 목록이 아닙니다.

예를 들어 `Senior Product Designer`를 주로 찾더라도 Staff, Lead, UX/UI, Growth 또는 다른 유사 역할이 실제 업무 범위와 요구 수준 측면에서 잘 맞으면 추천 대상이 될 수 있습니다.

내부적으로는 다음처럼 해석합니다.

- **Core target**: 가장 중심이 되는 역할 방향
- **Consider if fit**: 실제 업무가 맞으면 함께 볼 수 있는 역할
- **Hard exclude**: 사용자가 명확히 원하지 않는 역할이나 조건

경력이 많은 사용자의 Strong match는 직무명이 같다는 이유만으로 판단하지 않고, 실제 문제 유형, 오너십 범위, 성과, 전문성, 도메인 경험, 리더십 같은 근거를 함께 사용합니다.

## 최초 1회 설정

1. ChatGPT에 Gmail과 Google Drive를 연결합니다.
2. `prompts/01-bootstrap.md`를 엽니다.
3. 프롬프트 전체를 새 ChatGPT 대화에 붙여넣습니다.
4. ChatGPT가 구직 방향과 경력 근거를 대화형으로 수집합니다.
5. 개인 커리어 프로필과 새 Google Sheet Tracker를 생성합니다.
6. 기존 지원 이력이 있으면 선택적으로 가져올 수 있습니다.
7. Gmail 채용 알림 발신자를 찾거나 입력하고 사용자가 확인합니다.
8. ChatGPT가 반복 Scheduled Task를 생성합니다.
9. 설정 검증 테스트를 실행합니다.

별도 프로그램, Python 스크립트, 터미널 명령어, 서버, GitHub Action은 필요하지 않습니다.

## 개인 커리어 프로필

권장 파일명:

`Job_Mail_Collector_Profile.md`

raw Markdown 생성 또는 읽기가 지원되지 않으면 동일한 Markdown 내용을 담은 비공개 Google Doc을 사용할 수 있습니다.

프로필에는 다음과 같은 정보가 들어갑니다.

- 커리어 배경
- 주요 구직 방향
- 실제 업무가 맞으면 함께 볼 수 있는 유사 역할
- 차별화된 강점과 오너십 범위
- 스킬과 전문 영역
- 정량 또는 정성적 성과
- Leadership 경험
- 도메인 및 근무 조건
- 취업 자격과 스폰서십 처리
- 명시적 제외 조건과 주의 조건

현재 프로필 스키마는 `profile_version = 2`입니다.

이력서 버전 추적은 핵심 기능에서 제거했습니다.

## Tracker Sheet

기본 파일명:

`Job_Mail_Collector`

탭:

- `Config`
- `Sources`
- `Tracker`
- `Control`

Tracker는 정확히 13개 열을 사용합니다.

```text
Status
Company
Title
Location
Salary
WorkMode
Notes
Link
ReceivedAt
AppliedAt
RespondedAt
Result
Source
```

불필요한 복잡성을 줄이기 위해 아래 필드는 제거했습니다.

- ATS
- ResumeVersion
- Channel
- RejectionStage

`Source`를 출처 필드 하나로 사용합니다. 특정 공고에서 리크루터나 에이전시 정보가 중요하다면 `Notes`에 남깁니다.

`ReceivedAt`은 유지합니다. 사용자가 공고를 발견한 날이 아니라 며칠 뒤 Tracker를 다시 보고 지원할 수 있기 때문에, 공고가 언제 들어왔는지 확인할 가치가 있습니다.

현재 운영 스키마는 `config_version = 4`입니다.

## 예약 작업 누락 자동 복구

워크플로는 매일 예약 작업이 반드시 성공했다고 가정하지 않습니다.

`Control.last_successful_scan_date`에 마지막으로 정상 처리된 현지 날짜를 기록합니다.

매 실행마다:

- 첫 실행은 전날을 처리
- 이후에는 마지막 성공 날짜 다음 날부터 어제까지 모두 처리
- 예약 작업이 하루 이상 빠졌다면 다음 정상 실행에서 자동으로 누락 기간을 따라잡음

Scheduled Task 결과 맨 위에는 실제 처리 기간을 표시합니다.

프로필, Tracker, Gmail 소스 검색 등 핵심 처리가 끝나기 전에는 성공 날짜를 앞으로 넘기지 않습니다. Sheet 쓰기가 막혔더라도 전체 변경 내용을 TSV fallback으로 완전하게 반환했다면 해당 기간은 처리 완료로 볼 수 있습니다.

## 발신자보다 메일 내용을 먼저 분류합니다

같은 발신자가 항상 같은 종류의 메일만 보내는 것은 아닙니다.

하나의 주소에서 채용 추천 메일과 지원 확인 메일이 모두 올 수 있습니다.

따라서 관련 메일은 다음을 함께 보고 분류합니다.

- 발신자
- 제목
- 본문

예상 분류:

- 채용 공고 알림
- 지원 확인
- 리크루터 제출 근거
- 회사 또는 리크루터 회신
- 마케팅/뉴스레터
- 판별 불가

이렇게 하면 알려진 채용 알림 발신자라는 이유만으로 지원 확인 메일을 새 공고로 잘못 수집하는 문제를 줄일 수 있습니다.

## 일일 자동화

예약 시간이 되면 ChatGPT는 다음을 수행합니다.

1. 누락된 날짜까지 포함해 처리 기간 계산
2. Config, Control, Sources, 개인 프로필 로드
3. Tracker 전체 읽기 완전성 검증
4. 활성화된 채용 알림 소스를 전체 대상 기간에서 검색
5. 다이제스트 메일을 개별 공고로 분리
6. 메일을 용도별로 분류
7. 회사, 직무, 지역, 급여, 근무 형태, 출처, 링크 추출
8. 현재 실행 내 중복 제거
9. 명시적 하드 필터 적용
10. 사용자의 실제 경력과 차별점을 기준으로 적합도 평가
11. 검증된 Tracker 이력과 비교
12. 명확한 지원 및 회신 근거 대조
13. 허용된 경우 Tracker 자동 업데이트
14. 추천 공고, 소스 상태, Human review, Diagnostics 반환
15. 핵심 처리가 정상적으로 끝난 뒤 성공 날짜 업데이트

## 지원 확인과 회신은 Gmail을 한 번에 읽어 대조합니다

지원 또는 회신 감지가 켜져 있으면 Applied 회사마다 Gmail을 따로 검색하지 않는 것을 기본으로 합니다.

대신 대상 기간의 메일을 한 번 넓게 읽고, 지원 확인, 리크루터 제출, 회사 회신 가능성이 있는 메일을 분류한 뒤 Tracker의 관련 행과 대조합니다.

특정 애매함을 해결해야 할 때만 추가 검색을 합니다.

명확한 지원 근거 예:

- 회사 또는 ATS가 보낸 지원 확인 메일
- 특정 회사와 직무에 대해 리크루터가 지원서, 프로필, 이력서를 제출 또는 전달했다고 명확히 말한 메일

`제출할 수도 있다`, `전달해볼 수 있다`처럼 미래 가능성만 말한 경우에는 자동 상태 변경을 하지 않고 Human review로 보냅니다.

## Tracker 읽기 완전성 검증

공고나 지원 내역이 Tracker에 없다고 판단하기 전에 실제로 읽은 Tracker 행 수와 `Control.tracker_data_rows`를 비교합니다.

전체 읽기가 확인되지 않으면:

- 부재 판정 금지
- 과거 중복 확정 금지
- 지원/회신 상태 대조 중단
- 성공 날짜 업데이트 금지

부분 데이터로 `없다`고 판단하지 않습니다.

## 회사명 불확실성 처리

낯선 법인명, 브랜드명, 계열사명만 보고 모회사를 추정하지 않습니다.

두 공고가 같은 것처럼 보여도 회사 정체성이 확실하지 않으면 자동 병합하지 않고 `suspected duplicate`로 Human review에 보냅니다.

## 지원 상태 추적

명확한 근거가 있으면 다음을 업데이트할 수 있습니다.

- `Status = Applied`
- `AppliedAt`
- `RespondedAt`
- `Status = Closed`
- `Result = Rejected` 또는 다른 명시적 최종 결과

ATS 플랫폼이나 탈락 단계는 저장하지 않습니다.

지원 확인 메일이나 명확한 리크루터 제출 근거가 없다면 사용자가 직접 Applied로 변경해야 할 수 있습니다.

## 무응답 확인

기본 추천값은 지원 후 14일 동안 회신이 없는 건을 표시하는 것입니다.

무응답이라는 이유만으로 자동으로 Closed 처리하지는 않습니다.

## 채용 알림 소스 상태 점검

매 실행마다 활성화된 각 채용 알림 소스의 메일 수를 표시합니다. 0통인 소스도 숨기지 않습니다.

주요 소스가 모두 예상 밖으로 0통이면 채용 알림 설정, 발신자 패턴, 수신 계정 설정을 확인하라는 경고를 표시합니다.

## Tracker 자동 쓰기와 fallback

Google Drive 쓰기 작업이 가능하고 권한이 허용되면 새 후보와 명확한 상태 변경을 Tracker에 직접 기록합니다.

예약 실행에서 쓰기 승인이 필요하거나 쓰기 기능을 사용할 수 없다면, 변경 예정 내용을 정확한 13열 TSV로 반환하고 자동 쓰기가 적용되지 않았다고 명확히 알립니다.

## 설계 원칙

- **설문지가 아니라 대화.** 사용자는 자연스럽게 답합니다.
- **사람을 먼저 이해하고 조건을 좁힘.** 경력자는 직함과 연차만으로 판단하지 않습니다.
- **직무명보다 실제 업무 범위.** 명시적으로 제외하지 않은 유사 역할은 실제 적합도를 봅니다.
- **실제로 필요한 필드만 유지.** ATS, ResumeVersion, Channel, RejectionStage는 제거했습니다.
- **예약 작업 누락 자동 복구.** 실패한 날짜의 공고가 조용히 사라지지 않게 합니다.
- **메일은 내용으로 분류.** 발신자 주소만으로 용도를 판단하지 않습니다.
- **회신 대조는 한 번에.** 회사별 반복 Gmail 검색을 기본으로 하지 않습니다.
- **없는 링크와 회사 관계를 만들지 않음.** 알 수 없는 것은 알 수 없는 상태로 둡니다.
- **부분 Tracker 읽기로 부재를 판정하지 않음.** 완전성 검증을 먼저 합니다.
- **자동 쓰기 실패 시 안전한 fallback.** 정확한 TSV를 반환합니다.
- **지원 상태를 추측하지 않음.** 명확한 근거가 있어야 자동 변경합니다.

## 버전

현재 버전:

- `config_version = 4`
- `profile_version = 2`

Version 4는 Tracker를 13개 핵심 필드로 단순화하고 예약 작업 누락 복구를 추가합니다.
Profile version 2는 개인 프로필에서 이력서 버전 추적을 제거합니다.
